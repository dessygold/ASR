Nexus IQ Database Dashboard Update – Test and Production

Please update the Database section of the dedicated nexusiq.yaml Grafana dashboard to use AWS RDS metrics collected through YACE.

The Nexus IQ application Pod/JMX scrape (job="nexusiq") does not expose database, JDBC, HikariCP, DBCP2, SQL, or connection-pool metrics. The current database panels use Atlassian/HikariCP metrics and are not applicable to Nexus IQ.

Nexus IQ database metrics are available through the CloudWatch/YACE scrape path:

job="yace"
tag_Application="Nexus IQ"
The RDS metrics were validated in both Enterprise Test and Enterprise Production. The environment-specific labels are:

Test:
cluster="enterprise-test-cluster"
tag_Environment="test"

Production:
cluster="enterprise-prod-cluster"
tag_Environment="prod"
Because the same nexusiq.yaml dashboard is deployed to both test and production, please do not hard-code either the test or production cluster/environment values. Use the existing dashboard cluster/environment variables if available; otherwise, add appropriate dashboard variables and use them in the RDS queries.

Recommended common RDS selector:

job="yace",
cluster=~"${cluster:regex}",
tag_Application="Nexus IQ",
tag_Environment=~"${environment:regex}"
If the dashboard does not currently have $cluster and $environment variables, please add them or use the existing dashboard/environment variable convention used by other Grafana dashboards.

Do not use these Nexus IQ application-Pod filters in the RDS panel queries:

job="nexusiq"
namespace="nexusiq"
pod=~"$pod"
The RDS metrics are emitted by YACE in the monitoring namespace and are associated with Nexus IQ through the RDS tags and cluster labels.

Replace the current Database Latency panel queries—which currently use DBCP2/HikariCP pool metrics—with:

aws_rds_read_latency_average{
  job="yace",
  cluster=~"${cluster:regex}",
  tag_Application="Nexus IQ",
  tag_Environment=~"${environment:regex}"
} * 1000
aws_rds_write_latency_average{
  job="yace",
  cluster=~"${cluster:regex}",
  tag_Application="Nexus IQ",
  tag_Environment=~"${environment:regex}"
} * 1000
Use legends:

Read Latency
Write Latency
Retain/set the unit as:

milliseconds (ms)
The multiplication by 1000 converts the RDS latency values from seconds to milliseconds.

Replace the current Database Reads/Writes panel queries—which currently use Atlassian/HikariCP metrics—with:

aws_rds_read_iops_average{
  job="yace",
  cluster=~"${cluster:regex}",
  tag_Application="Nexus IQ",
  tag_Environment=~"${environment:regex}"
}
aws_rds_write_iops_average{
  job="yace",
  cluster=~"${cluster:regex}",
  tag_Application="Nexus IQ",
  tag_Environment=~"${environment:regex}"
}
Update the panel title to:

Database Read / Write IOPS
Use legends:

Read IOPS
Write IOPS
Consider adding a separate database connections panel using:

aws_rds_database_connections_average{
  job="yace",
  cluster=~"${cluster:regex}",
  tag_Application="Nexus IQ",
  tag_Environment=~"${environment:regex}"
}
Additional validated RDS metrics available for future Nexus IQ panels include:

aws_rds_cpuutilization_average
aws_rds_freeable_memory_average
aws_rds_free_storage_space_average
aws_rds_disk_queue_depth_average
aws_rds_read_throughput_average
aws_rds_write_throughput_average
Please avoid default 0 for RDS panels during initial implementation. If the YACE/RDS data source is unavailable, the dashboard should show no data rather than a misleading zero value.
