1. Replace the current Database Latency panel targets
The current panel is not actually measuring latency; it is attempting to calculate HikariCP/DBCP connection-pool utilization.

Replace the targets section for panel ID 38 with the following:

"targets": [
  {
    "datasource": {
      "type": "prometheus",
      "uid": "$datasource"
    },
    "editorMode": "code",
    "expr": "aws_rds_read_latency_average{job=\"yace\", cluster=\"enterprise-test-cluster\", tag_Application=\"Nexus IQ\", tag_Environment=\"test\"} * 1000",
    "legendFormat": "Read Latency",
    "range": true,
    "refId": "A"
  },
  {
    "datasource": {
      "type": "prometheus",
      "uid": "$datasource"
    },
    "editorMode": "code",
    "expr": "aws_rds_write_latency_average{job=\"yace\", cluster=\"enterprise-test-cluster\", tag_Application=\"Nexus IQ\", tag_Environment=\"test\"} * 1000",
    "legendFormat": "Write Latency",
    "range": true,
    "refId": "B"
  }
]
Keep the panel title:

"title": "Database Latency"
Keep or set the field unit to:

"unit": "ms"
The * 1000 is needed because AWS RDS read/write latency values are measured in seconds, while the Grafana panel is configured to display milliseconds. AWS documents RDS ReadLatency and WriteLatency in seconds.

Important production consideration
The supplied queries are validated for Enterprise Test only because they use:

cluster="enterprise-test-cluster"
tag_Environment="test"
Before using the same code for production, validate the production RDS labels with:

aws_rds_info{
  cluster="enterprise-prod-cluster",
  job="yace",
  tag_Application="Nexus IQ"
}
Then update the production dashboard query with the production cluster/environment values, or add appropriate dashboard variables if the same dashboard definition must support both test and production.

Handoff overview for the next agent
Nexus IQ Pod/JMX scrape uses job="nexusiq" and exposes JVM/JMX metrics only.

Nexus IQ database metrics are not in the JMX scrape.

The Nexus IQ backend is external PostgreSQL/RDS.

Database infrastructure metrics are already collected by YACE from AWS CloudWatch under:

job="yace"
The Nexus IQ test RDS resource is uniquely identifiable through:

cluster="enterprise-test-cluster"
tag_Application="Nexus IQ"
tag_Environment="test"
Existing database panels use unsupported Atlassian/HikariCP metrics and should be replaced with:

aws_rds_read_latency_average
aws_rds_write_latency_average
aws_rds_read_iops_average
aws_rds_write_iops_average
aws_rds_database_connections_average
Use * 1000 for RDS read/write latency panels if the Grafana panel unit remains milliseconds.
