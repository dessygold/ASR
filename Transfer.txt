Hi , I’ve picked up the Nexus IQ Grafana Dashboard work item and want to confirm the approach with you before I build anything.

What I know

Sonatype confirmed on Nov 3 that IQ has no native Prometheus endpoint. Its metrics are JSON only, at :8071/metrics, and we have to convert them ourselves. They’ve opened a feature request, with no timeline.
The existing nexusiq-overview dashboard in grafana-dashboards looks like a copy of the Jira/Confluence one (Atlassian/Tomcat metric names, job="nexusiq"). In Grafana it shows No data or N/A, and its default data source isn’t set to VictoriaMetrics.
IQ isn’t deployed in dev (app-nexusiq.yaml skips dev), so I’d validate in test.
Nexus Repository has a scrape manifest in support-manifests. IQ doesn’t, and it has no basic auth on 8071, so Nexus’s file can’t just be copied.
Options I see

json_exporter, as a sidecar or separate pod, with a VMServiceScrape in the nexus-iq repo’s support-manifests. Metrics land in Victoria, which meets the work item. It needs a new image through ECR and cDSO, and I haven’t confirmed whether the IQ chart allows a sidecar.
Grafana Infinity plugin (Bob has used it), which queries IQ’s JSON directly from Grafana. It’s quicker, but it’s a third-party plugin, it bypasses Victoria, and Core’s Grafana would need network access to IQ’s admin port in Enterprise.
Another approved exporter or translation method, if you know one, or wait for Sonatype’s native support (not realistic soon).
What I need from you

Which option do you prefer? Are third-party Grafana plugins like Infinity allowed?
If it’s the exporter route, where should it live: its own app repo (like yace) or in nexus-iq?
Can you point me to the right data source and how you validate metrics in test (I saw your TODO about port-forwarding to vmselect)?
Can I get access to the test Grafana and Explore to check what Victoria already has for the nexusiq namespace?
